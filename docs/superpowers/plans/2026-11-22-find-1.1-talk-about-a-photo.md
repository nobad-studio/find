# NOBAD Find 1.1.0: talk about a photo (Describe / Ask / Compare) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a photo's detail sheet the user can press Describe, ask a question about it, or compare it with a second
photo. Find answers locally with SmolVLM2-500M first, and with Qwen3-VL-2B as "Deeper analysis" only when this PC can
run it now. Answers stream in and are labelled as Find's reading.

**Architecture:**
- **Engine side:** one new worker process (`vision` role) holds at most one vision-language model. It runs llama.cpp's
  library (`llama.dll` + `mtmd.dll`, pinned build b12602) through `ctypes`, with no server, no port and no
  per-photo reload.
- **Decoding and requests:** pictures are decoded by Windows' decoders (as photo.py does today) and handed to mtmd as
  RGB buffers. The engine sends jobs (file ids already resolved to paths) and receives streamed tokens.
- **Pipe:** new methods and a `vision` event carry them to the Flutter detail sheet.
- **Models and runtime:** both are catalog entries, downloaded only after consent and checked by size + SHA-256.

**Tech Stack:** Python 3.11 engine (`nobadfind/`), ctypes, llama.cpp b12602 (CPU + Vulkan builds), Windows imaging
(winrt), Flutter UI (`ui_flutter/`), JSON-RPC pipe (`contract/`).

**Spec:** `docs/superpowers/specs/2026-11-21-find-visual-intelligence-design.md` (§4 Talk, §2 PC analyzer, "Phase 0
results", Release: 1.1.0) and `docs/superpowers/specs/2026-11-22-find-hardware-intelligence-design.md` (§8 Qwen, §6.3
allocation, §8b user control).

## Global Constraints

- **No Ollama, no llama.cpp server, no port.** The model runs inside Find's own worker process (spec "No Ollama").
- **Models:** SmolVLM2-500M Q8_0 answers first. Qwen3-VL-2B Q4_K_M is "Deeper analysis", offered only when
  `capability.assess` allows it now, and never automatic (HW spec §8).
- **One large vision model resident** at a time. One inference stream on a constrained (shared-memory) GPU.
- **Qwen settings:**
  - scene/relationship questions: 512 px, ≤ 160 image tokens, flash attention, 8-bit KV cache, `n_ctx` 1024,
    `n_ubatch` 256;
  - text questions: the "short answers" setting (measurements.md: identical answers, −21% RAM).
- **SmolVLM2:** 512 px; `n_ctx` 1024, flash attention, 8-bit KV, `n_ubatch` 256 (measured −17% RAM, same speed).
- **Downloads:** every model file and the llama.cpp runtime are catalog entries (revision, size, SHA-256) fetched only
  through `embed._fetch_verified` after the user's consent (`model_download` with `consent: "DOWNLOAD"`).
- **Pictures:** decoded only by Windows' decoders (BitmapDecoder); never handed to llama.cpp's own image loader
  (stb_image) as a file.
- **Files only by result id;** names-only and secret files are refused ("a preview is the content" rule, like
  thumbnails).
- **No model's reading of Hindi text is shown as fact** (spec Phase 0): a text answer that contains Devanagari is
  shown with "may not be exact", and stored OCR text is shown first.
- **The vision worker** joins the WORKERS job (memory cap) and uses `winapi.worker_priority()`. It runs only when
  the governor level isn't PAUSED.
- **Every answer is labelled** "Find's reading of this photo". Copy is allowed. "Keep this description" stores the
  description only on the user's press.
- **No background VLM indexing in 1.1.0** (L3 deep pass is out of scope).
- **Rules from AGENTS.md:** new pipe methods update `contract/methods.schema.json`, `contract/README.md`, a transcript
  (`python tests/test_rpc_contract.py --record`) and the Dart side together. New settings go in `const.DEFAULTS` +
  `settings.coerce` + a Settings row + the schema. Tests: `python -m pytest -q tests`, `python -m pyflakes
  nobadfind tests`, `flutter analyze`, `flutter test`.

## Review Focus

1. **The photo changes or disappears** between opening the sheet and asking (moved, deleted, edited). Expected: a
   plain "This photo is no longer there" answer and no worker crash. Owner: Task 6. Test:
   `test_vision_ask_missing_file`.
2. **The user asks again, or closes the sheet, while an answer streams.** Expected: the old answer stops
   (`vision_cancel` or a new ask cancels it), tokens of the old answer never appear under the new question, and the
   worker stays loaded. Owner: Task 5/6. Tests: `test_new_ask_cancels_old_stream`,
   `test_cancel_mid_stream_keeps_model`.
3. **Memory runs short while loading or answering** (another app takes RAM/VRAM between the check and the load).
   Expected: the allocation failure is caught in the worker, which says "Not enough memory right now (needs about
   X)", stays alive and unloads; nothing is retried in a loop. Owner: Task 3/5. Test:
   `test_alloc_failure_reports_and_unloads`.
4. **A huge, corrupt or unsupported picture** (40 MB TIFF, truncated JPEG, HEIC without codec, 80 Mpx panorama).
   Expected: a refusal with a reason within the decoder limits (photo.py MIN/MAX bytes and pixels), not a hang.
   Owner: Task 4. Test: `test_decode_for_vlm_refuses_unusable`.
5. **A very long or hostile question** (10,000 characters, control characters, "ignore your instructions..." text in
   the picture or the question). Expected: the question is cut to 500 characters, control characters are removed,
   and the answer is labelled as the model's reading. Nothing the model writes is executed or used as a path.
   Owner: Task 4/7. Test: `test_question_is_cleaned_and_capped`.

### Task 6: The vision worker process and engine API (`nobadfind/vlm/worker.py`, `nobadfind/api.py`)

**Files:**
- Create: `nobadfind/vlm/worker.py`
- Modify:
  - `nobadfind/api.py`: `vision_state()`, `vision_describe(file_id)`, `vision_ask(file_id, question)`,
    `vision_compare(a, b, question=None)`, `vision_cancel()`, `vision_keep(file_id, text)`;
  - `nobadfind/engine.py`: worker lifecycle and the idle release;
  - `nobadfind/store.py`: table `vdesc(file_id PRIMARY KEY, text, model, at)`, with delete cascading with files.
- Test: `tests/test_vision_api.py`

**Interfaces:**
- Consumes: `Session`, `models.talk_models`, `models.runtime_for`, `capability.assess` (PR #16; if it's absent,
  `models.capable` only), and the governor level.
  - Release fix (2026-11-22): a fallback (`models.capable` + free RAM, `api.talk_fits`) was used until PR #16
    merged. Removed in 1.2.0 (the rest plan, Task 1): talk uses `capability.assess` only
    (`tests/test_vlm_progress.py::test_capability_module_is_used_when_present`, `test_no_fallback_left`).
- Produces:
  - The worker runs in a child process (`multiprocessing`, spawn) with `jobs.join_workers()` and
    `winapi.worker_priority()`. It takes jobs `{"op", "paths", "question", "model", "settings", "gpu_layers"}` from a
    pipe and sends back `{"t": "token", "s"} | {"t": "done", "text"} | {"t": "error", "why"} | {"t": "state", ...}`.
    It unloads after 180 s idle (`embed.Lazy.IDLE`).
  - `Api.vision_*` returns `{"ok", "error", "job"}` at once. Tokens arrive as the `vision` event
    `{"job", "state": "loading" | "answering" | "done" | "error" | "cancelled", "text", "model", "note"}`.
  - **Resolving files:** a file id becomes a path through the files table. Names-only and secret files are refused,
    and kinds other than image are refused. A missing file gives "This photo is no longer there".
  - **Model choice:** SmolVLM2. `vision_ask(..., deeper=True)` uses Qwen if `assess` allows it now, else the reason
    ("Not now: only 3.0 GB free, Qwen needs about 2.4 GB plus margin"). The model switch unloads the other model
    first.
  - **Text questions:** if the photo has OCR chunks, their text is sent first as
    `{"state": "done", "note": "Text read from the photo"}` and the model runs only on `more=True`.
  - **Kept descriptions:** a description the user keeps (`vision_keep`) is also stored as one text chunk of that
    photo, so name/words/meaning search can find it. Results it matches say "your kept description matches"
    (provenance kept apart from OCR and from the picture's look). Only user-kept text is added; nothing is
    generated in the background (the caption test failed: captions stay out of ranking).
    Test: `test_kept_description_is_searchable_and_labelled`.
